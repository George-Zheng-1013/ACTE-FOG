# 实验二 公平比较：第一批（seed=1）结果

执行日期：2026-10-22。协议版本：`docs/2、公平比较.md`（2026-10-22 修订版）。批次：第一批，仅 seed=1。

性质：流程与设计验收批次。单种子、无置信区间，不宣称超过历史 0.932，也不把任一模块判为稳定有效。

## 0. 两个配方版本

| 版本 | 目录 | 训练配方 | 用途 |
|---|---|---|---|
| v1 | `results/fair_ctrl_v2/` | 固定参数：CNN lr 8e-3、batch 64、patience 10、监控加权 BCE；ET max_features=16 | 固定参数参照表（协议 2.7.3 要求与调参结果分表） |
| **v2** | `results/fair_ctrl_v2_tuned/` | 等预算验证集调参后冻结：CNN lr 8e-4、batch 64、patience 20、监控验证 AUROC；ET max_features=32、min_samples_leaf=3 | **本批主表** |

v1 出现的问题是早停信号失效：验证损失逐轮振荡幅度（均值 0.09–0.18）是 `min_delta`（1e-3）的 93–182 倍，最优轮落在噪声低点上（第 3–5 轮），CNN 训练在 13–15 轮就停止，测试 AUROC 只有 0.8913。v2 按协议 2.7.3 先做等预算调参再冻结，CNN 回到 0.9230。

## 1. 结论（v2 主表）

| # | 结论 | 依据（测试 AUROC） |
|---|---|---|
| 1 | 同输入（左踝三轴 gyro）下 CNN 明显优于 ET | 0.9230 对 0.8187，差 +0.1043；AUPRC 差 +0.2551 |
| 2 | 带通滤波对两个模型都近乎无影响 | 开启−关闭：CNN −0.0030，ET −0.0059 |
| 3 | 补到四部位 24 通道对 ET 有大增益、对 CNN 无增益 | ET +0.0795（0.8187→0.8982），CNN −0.0112（0.9230→0.9119） |
| 4 | 换成 132 维手工特征，ET 追平 CNN | F1 0.9232 对 M 的 CNN 0.9230 |
| 5 | 协调 12 维无可分辨贡献 | F1 0.9232 对 F6 0.9236，差 −0.0003 |
| 6 | 七窗居中平滑对 CNN 有正贡献，对 ET 无 | CNN +0.0143，ET −0.0002 |

第 2、5 条与 v1 的判断不同（v1 认为滤波对 CNN 有 −0.0235 的负贡献、协调块有 +0.0008 的正贡献）。差别来自训练配方而非数据，见第 7 节。

两点必须说明：

- **CNN 的搜索面是平的**。六个配置的验证 AUROC 只跨 0.897–0.903，极差 0.006，而单配置的种子标准差就有 0.004–0.011。选中的 cnn0 与最差的 cnn4 差距小于种子噪声。真正带来 +0.0317 的是早停监控量从加权 BCE 改为验证 AUROC、patience 从 10 提到 20，不是超参数本身。
- **ET 的选择落在噪声里**。et5 与 et3 只差 0.0009（种子标准差 0.0021），测试端反而 et5 更低 0.0077（0.8187 对 v1 的 0.8264）。这是选择噪声直接吃掉 0.008 测试分的实例，也说明 v2 的 ET 数值不能解释为「ET 变差了」。

## 4. 协议取值（v2）

P_ref 与协议 2.5.1 一致：S0＝左踝三轴 gyro；0.5–20 Hz 四阶 Butterworth 零相位滤波（逐通道按最大连续有效段，>30 点才滤）；逐窗逐通道去均值（仅用有效观测，全缺失通道均值置 0，共 11266 个窗-通道单元走此回退）；不标准化；缺失填 0；无缺失提示；无平滑。

| 项 | 取值 |
|---|---|
| 训练样本权重 | w_c = N_train/(2·N_train,c) → 0.6446 / 2.2283，两模型共用 |
| CNN | OfficialCNN，8353 参数（3 通道）/ 11377 参数（24 通道）；AdamW lr 8e-4、wd 4e-4；batch 64；L2 1e-3 施加于除 fc2 外的 Conv/Linear；早停在 12–16 号患者的**验证 AUROC** 上，patience 20、min_delta 1e-4、上限 60 轮 |
| ET | 500 棵、min_samples_leaf=3、max_features=32（固定整数）、class_weight=None、同一 sample_weight |
| 阈值 | 验证集 0–1、步长 0.001，敏感度与特异度绝对差最小，并列取最小阈值 |
| 设备 | RTX 4060 Laptop（torch 2.11.0+cu130）；ET 在 CPU |

**验证患者的三种用途**：12–16 号同时用于 CNN 早停、配方选择、阈值选择。这是协议允许的安排，但代价是**验证指标完全没有泛化含义**，任何比较只看测试列；而测试列本身已被历史开发反复查看，仍属内部探索性比较。

## 9. 必须标注的限制

1. **验证集三用**（早停 + 选配方 + 选阈值），验证列无泛化含义；测试列亦属反复查看过的内部集。
2. **单种子**。所有差值无标准差；0.01 量级的差（滤波、协调块、平滑对 ET）在单种子下不可区分。
3. **调参面是平的**。CNN 六配置极差 0.006 小于种子标准差，ET 前两名差 0.0009。因此「选中配置」不应被解读为最优超参数；它是规则下的一个确定选择。
4. **ET 因选择噪声损失 0.008 测试分**。这是选择流程本身的代价，不是模型差异。
5. **CNN 训练仍受配方影响大**（同一数据，v1 与 v2 差 0.03）。任何「CNN 的能力」表述必须绑定配方。
6. **F 表只对 ET 成立**，不推及 CNN；CNN 的输入贡献只由 S 表回答。
7. **平滑是离线操作**（使用未来窗口），不能据此声称实时性。
8. **耗时不可作成本结论**：CNN 单次 22–31 s、ET 1–3 s（RTX 4060，6012 训练窗）。

## 10. 复现

工作目录 `背景材料/fogstar_final_engineering/`，Python 为 `D:\Develop\miniconda\envs\py312\python.exe`（3.12.13；torch 2.11.0+cu130；scikit-learn 1.7.1）。

```
# 1) 等预算调参（约 6 分钟）
python -m src.fair_v2.tune --out results/fair_ctrl_v2_tuned --device cuda

# 2) 用冻结配方重跑第一批
for e in M P1 S5 F1 F6 P6; do
  python -m src.fair_v2.run --exp $e --seed 1 --device cuda \
    --out results/fair_ctrl_v2_tuned \
    --cfg-json results/fair_ctrl_v2_tuned/tuning/selected_config.json
done

# 3) 验收与汇总
for e in M P1 S5 F1 F6 P6; do python -m src.fair_v2.verify --exp $e --out results/fair_ctrl_v2_tuned; done
python -m src.fair_v2.report --out results/fair_ctrl_v2_tuned
```

每个实验目录含：`protocol.json`、`windows.csv`、`exclusions.csv`、`weights.csv`、`coverage_*.csv`、`environment.json`、`run_config.json`、`metrics.json`、`comparison.json`、`comparison_by_seed.csv`、`acceptance.json`，以及每个模型子目录的 `model.pt` / `model.joblib`、`fit_info.json`、`view.json`、`{val,test}_predictions.csv` 与同名的 `.npz` 精确副本。调参目录另有 `protocol.json`、`tuning_results.csv`、`tuning_aggregate.csv`、`selected_config.json`。
