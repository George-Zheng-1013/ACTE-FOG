## 当前学习检查点：读懂主入口的三件事

先看 `src/final_model.py:55–60`，不急着重跑。以下代码仅从原入口摘出用于讲解，不构成一个可单独运行的脚本。

训练：

```python
model.fit(X[tr][:, idx], y[tr])
```

X 的一行代表一个 2 秒窗口，tr 筛选 1–11 号训练患者，idx 从 132 维中选择 72 维。因此实际训练输入为 6012×72，y[tr] 是这 6012 个窗口的 FoG 标签。不是把原始 120×24 信号直接喂入树模型。

推理：

```python
p[te] = model.predict_proba(X[te][:, idx])[:, 1]
```

te 筛选 17–22 号患者，输入为 2436×72。模型输出每窗属于 FoG 类别的估计概率；这里没有把 y[te] 传进去。该数值没有经过额外校准验证，不能直接当作临床风险概率。

选阈值与评价：

```python
thr = eer_threshold(y[va], p[va])
metrics(y[te], p[te], thr)
```

va 对应 12–16 号患者的 2151 个窗口。原代码先对验证和测试概率各自平滑，再用验证标签选阈值 0.32；测试仅用这个既定阈值评价。p≥0.32 判为 FoG，p<0.32 判为非 FoG。

学习验收：能解释训练为何需要 y[tr]、推理为何不需要 y[te]，以及阈值为何从验证集选。先掌握这三点，再深入 `context_probe.py` 的 132 维特征构建。

## 1. 先建立正确的全流程概念

ACTE-FoG 的原始链路是：

```text
sensor_data.csv
  → 按 subject/session/task 分组
  → 各轴连续有效片段滤波
  → 120 点窗口，每次前进 30 点
  → 去均值、缺失处理、132 维统计/频域/协调特征
  → 选双踝 60 维 + 全身协调 12 维
  → 用训练患者拟合 ExtraTrees
  → 验证/测试患者输出 FoG 概率
  → 同片段概率平滑
  → 仅用验证标签确定阈值
  → 测试集评估与保存结果
```

“训练”是从训练患者的特征和 FoG 标签学习分类规则；“推理”是在不使用待预测标签的条件下输出概率；“评估”才把概率和真实标签比较。现有原始程序把三者放在同一次运行中。

ACTE 不是端到端深度网络：132 维特征由代码预先定义，ExtraTrees 学习如何组合其中的 72 维。它没有训练 epoch/loss 曲线，不能用 CNN 的日志预期来判断是否运行。

## 3. 第二个检查点：读懂 ACTE 主入口

打开 `src/final_model.py`，按下面顺序阅读：

| 位置 | 要理解的内容 |
|---|---|
| `feature_indices():17` | 五组各取双踝 12 维，再取 12 维全身协调，共 72 维 |
| `main():55–56` | 载入缓存；患者 1–11 训练、12–16 验证、17–22 测试 |

| `main():60–61` | 用相同阈值评估验证与测试，并保存 summary、predictions |

注意：真实 FoG 标签在 `fit` 与评估时出现，在 `predict_proba` 中不作为输入。activity 没有输入最终树模型；它可用于离线误差分层。

## 7. “训练后预测”与“保存后独立推理”还差什么

原 ACTE 每次运行都先 fit，不保存树模型；因此第一轮命令证明的是同次运行内的训练、测试推理和评估。

若把独立推理纳入第一阶段验收，下一步只补最小闭环：保存模型、72 维特征顺序、阈值、解码模式/参数和依赖版本；在新进程加载后，对同一有序测试片段重算原始及平滑概率，并用数值一致性检查验收。批量概率平滑需要片段身份和顺序，不能随意打乱单窗。

这仍是后续待确定的补充任务；本轮没有新建模型保存或部署代码。
